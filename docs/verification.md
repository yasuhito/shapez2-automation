# 実機検証の記録

2026-10-10、shapez 2 1.2.0-rc3 / Steam build 24668948 / Windows Unity + Protonで確認しました。

## 公開ソースの検証

- .NET SDK 9.0.120でMODとメタデータユーティリティのビルド成功。
- Python構文確認と模擬バックエンドの単体テスト4件成功。
- 公開直前のMODのSHA-256: `747b916607564321e860431171f10c0964b6384046be908fa239010e39d8ccb2`。ローカル出力と専用フォルダのDLLが一致。
- ゲームDLL、アセット、セーブ、個人ログ、画像、第三者ソースは公開対象から除外。

## ゲームで確認したこと

最新DLLで、JSONによる通常モード選択、新規テスト開始、確認欄への同意と画面終了、停止、採掘島と27部品の配置、再開、5個以上の実納品を確認しました。納品判定はゲーム本体が行います。

シード2162800の同じ操作列を複数回実行し、27段階すべての建物ハッシュが以前の実行と一致しました。最終建物ハッシュは `635347905a073c6f1456862254602524750ec59710af7960cb10a589ff4d0b92` です。

以前の同じ配置・操作キュー実装で、非フォーカス状態の処理、配置と所有物削除の繰り返し、停止状態復元、配置取消、メニュー復帰、占有・床外・別セーブ・所有外削除の拒否を確認しました。最新実行はフォーカスありで実施したため、最新DLLの非フォーカス再検証とは区別します。

ゲーム自身のPNG撮影APIから工場画面を保存しました。画像と生の要求・応答はローカルにのみ保存し、公開していません。

## 残る制限と未解決事項

- カメラAPIは制御オブジェクトが依存コンテナに登録されておらず、`No instance bound to CameraController`で失敗します。カメラ移動は検証済み機能に含めません。
- 最新起動のゲームログにはメニューのウォームアップと追加コンテンツUIを含む7件の例外があります。起因の切り分けは未完了です。納品確認は成功しましたが、例外ゼロとは報告しません。
- 建物ハッシュには島、設定、在庫、乱数、シミュレーション全体を含めません。同じ建物配置と実納品の確認は、完全なシミュレーションの決定性の証明ではありません。
- 固定tick送り、完全なsnapshot/restoreは未実装です。
- 通常の配置処理全体を再現した汎用APIではありません。MOD自身が開始した専用テストセッションに限定します。
- 他バージョン・Windowsネイティブ・macOSは未検証です。ゲームDLLのハッシュが異なると起動を拒否します。
- CIではPythonの確認と補助ツールのビルドを実施します。ゲームDLLが必要なMODビルドや実機テストは含みません。
